WHY ANOTHER MEDIA APP?

Because apparently I needed another homelab project.

I’ve been a developer for over 20 years. My home media servers worked brilliantly, but watching something meant too many apps, menus and faffing about. I wanted one place the whole family could use without a demonstration.

So I built Tellybox: my collection, live TV, 24/7 channels and on-demand content, together. With Codex by my side, a little local player became an ungodly number of evenings tinkering. It’s even wife-approved now.

Friends asked for their own version, so I turned the bits specific to my house into settings. Same code, your server, your services. It’s a geek’s hobby project I’m proud to share. Hopefully it saves you some faff too.

- James · developer, homelabber, serial tinkerer

01 · GET IT RUNNING

Run it on Linux. Set it up from any home computer.

I recommend a Linux server for Tellybox. Use PowerShell on your Windows computer or Terminal on your Mac to connect to it and run the commands below. Then finish setup in your normal browser, using the server’s LAN address.

This guide uses alex@192.168.1.50 as an example Linux login. Replace alex with your server username and 192.168.1.50 with its private LAN IP throughout. Give the server a stable address using a DHCP reservation or your usual network settings.

You’ll need a Linux server with Docker and at least one existing media service. Tellybox connects to Jellyfin, Dispatcharr and the other services you choose; it doesn’t install them or supply media. See what each integration adds ↓

This is an early-access release for home use. Start with a separate configuration and test your services before relying on it. Already running Tellybox? Use the update steps and keep your existing configuration volume.

STEP 1 · CONNECT TO YOUR LINUX SERVER

Get the server ready

Open PowerShell on Windows or Terminal on macOS and connect:

ssh alex@192.168.1.50

Your Linux server needs SSH enabled and your login configured. After connecting, commands in this terminal run on the Linux server. You do not need Docker installed on the Windows or Mac computer you are using to control it.

On the server, install Docker Engine and the Compose plugin using Docker’s instructions for your Linux distribution. Keep an existing working Docker installation. Install Git too. No GitHub account or sign-in is needed to download the public server source.

Check Docker from the connected terminal:

docker version
docker compose version

Both should show version information and Docker should be able to contact its engine. Your account needs permission to use Docker; if your installation requires it, prefix the Docker commands below with sudo.

Hosting on Windows or macOS with Docker Desktop is possible, but Linux is my recommendation. The steps here use Windows and Mac only to manage the Linux server.

STEP 2 · INSTALL FROM GITHUB

Clone Tellybox onto your server

The server source is at jharrisuk/tellybox-homelab, free for personal and non-commercial use. Run these commands in the terminal connected to your Linux server:

cd ~
git clone https://github.com/jharrisuk/tellybox-homelab.git
cd ~/tellybox-homelab

This creates ~/tellybox-homelab containing compose.yaml, .env.example and server. Run the remaining installation commands from that folder. If you already installed Tellybox, use its existing folder and the update steps instead of cloning another copy.

Create and edit the Docker settings file:

cp .env.example .env
nano .env

Set these two lines to your Linux server’s private LAN IP. This enables viewing and setup from your other home devices. Leave the relay setting unchanged for now.

TELLYBOX_BIND=192.168.1.50
TELLYBOX_SETUP_BIND=192.168.1.50

In nano, save with Ctrl+O, press Enter, then exit with Ctrl+X. Use the server’s actual private address, not 0.0.0.0, a public IP or your Windows/Mac computer’s IP. Allow ports 8082 and 8990 only from your trusted home network in the server’s network/firewall rules.

STEP 3 · IN THE PROJECT FOLDER

Start Tellybox

docker compose up -d --build --wait
docker compose ps

The first run downloads the image dependencies and builds the container. Wait for it to finish; the service should show as Up and healthy. It keeps running after you close the terminal, but the computer and Docker must stay running for anyone to watch.

Copy your one-use setup code with this command:

docker compose exec tellybox node -p "require('/config/bootstrap.json').token"

Keep that code for the next step. Don’t put it in screenshots or support messages. If it prints undefined, the installation has already been claimed: use its existing administrator password.

STEP 4 · IN YOUR NORMAL BROWSER

Open setup

From any computer on the same LAN, open http://SERVER_IP:8990 in your browser. For the example above that is http://192.168.1.50:8990. Enter your setup code, choose an installation-administrator password of at least 12 characters, and select Continue.

No SSH tunnel is needed for this LAN setup. The browser uses the Linux server’s address, not 127.0.0.1, which would mean the computer running your browser. Next time, sign in with your administrator password. Local viewing remains separate from installation administration.

Keep setup on your trusted home network. Never forward port 8990 on your router or put it on the public reverse proxy.

Optional encrypted SSH route for a separate server

Keep TELLYBOX_SETUP_BIND=127.0.0.1 on that server. On the computer running your browser, open a terminal and run, replacing the example user/IP:

ssh -N -o ExitOnForwardFailure=yes -L 8990:127.0.0.1:8990 alex@192.168.1.50

Leave that terminal open and browse to http://127.0.0.1:8990. The SSH connection encrypts the traffic between the computers. If local port 8990 is busy, use -L 18990:127.0.0.1:8990 and browse to http://127.0.0.1:18990.

STEP 5 · IN THE SETUP PAGE

Connect your services

Enable what you want. Jellyfin connects your local collection; Dispatcharr adds live TV and streamed titles. Use either, both, or add other integrations later.

Each service has an Enabled or Off badge. Click its row to expand the controls. Your relay status appears above the services.

  1. Open the service row, enable it and enter its address and required credentials.
  2. For Dispatcharr, tick the features you use: Live TV and 24/7, On-demand catalogue, Recordings or Catch-up.
  3. Select Save settings, then Test saved connection.
  4. Once it connects, select Apply & restart media.

Save keeps a draft. Apply puts it into use and briefly interrupts viewers. If the media service cannot start, the previous configuration is restored. Restarting the container keeps the last applied settings; it does not activate an unapplied draft.

If a service runs on the same computer as Tellybox, select Runs on this server. Tellybox fills in the host address and usual port; change the port if yours differs, then test the connection. “This server” means the computer running Docker, even when you open setup from another computer.

Where the media service runsWhat to choose
On the same Windows, Mac or Linux Docker hostSelect Runs on this server and check its port.
On another home machineUse its actual LAN address, such as http://192.168.1.60:8096.
In another container on a shared Docker networkUse its container DNS name and service port, such as http://jellyfin:8096.

Uncheck that option to enter a custom address. Same-server services must be reachable on a host port, including services running in other containers. If you only expose a service on a shared Docker network, use its container DNS name instead.

How the same-server address works

Inside Tellybox’s container, localhost means that container. The shortcut uses host.docker.internal, with a host-gateway mapping supplied by Compose for Linux. The service must accept connections from Docker; a service listening only on host loopback may need its listening address changed. See Docker’s networking instructions.

Jellyfin needs an API key and a dedicated viewer’s user ID. Dispatcharr VOD and recording controls need its personal API key. To request local copies through Seerr, fill in each destination’s server ID, quality profile ID and root folder to match its Radarr/Sonarr configuration. All three are required for that request type; leaving them blank still allows discovery. The specials checkbox controls season-zero requests.

Return here whenever you want to change connections or optional features. Blank secret fields keep their saved values. People, favourites and viewing controls stay in the normal Tellybox settings page.

STEP 6 · WHEN YOU’RE READY TO WATCH

Open Tellybox

In setup, open Addresses & local access and enter your server’s details. For the example server at 192.168.1.50:

SettingExample
Local playback addresshttp://192.168.1.50:8082
Trusted home networks192.168.1.0/24
Local hostnameslocalhost, 127.0.0.1, 192.168.1.50
Public address and relay fieldsLeave blank for home-only use.

The subnet must match your network; /24 is an example, not a value to copy everywhere. Save and Apply. You already enabled the LAN port in step 2.

Open http://SERVER_IP:8082 on your phone, TV or computer using the server’s actual IP. For this example, it is http://192.168.1.50:8082. The server keeps running after you close the SSH terminal.

Keep ports 8082 and 8990 off the public internet. For viewing away from home, follow the optional HTTPS relay setup. The apps use the same viewing address; see phone and TV setup.

LATER · KEEP YOUR SERVER UP TO DATE

Update the same installation

Back up your configuration first and choose a time when a brief playback interruption is acceptable. Connect to Linux as before and use the same project folder:

cd ~/tellybox-homelab
git status --short
git pull --ff-only

If Git reports local changes or cannot update cleanly, stop and resolve that before proceeding. Keep your existing .env and Docker configuration volume; do not copy .env.example over your settings.

After the pull succeeds, rebuild and replace the container:

docker compose up -d --build --wait
docker compose ps

Your settings, accounts and favourites remain in the existing volume. If your original project folder has a different name, use that folder throughout. Phone and TV app updates are offered separately in the apps.

Something didn’t work?

Git cannot download the source

Check the repository address is https://github.com/jharrisuk/tellybox-homelab.git and that your Linux server can reach GitHub over HTTPS. The public repository does not require an invitation or login.

Docker cannot connect

Check you are running the command inside the SSH connection to Linux. Check that Docker is running on that server and that your account has permission to use it.

The setup page won’t open

Use http://SERVER_IP:8990, including http://, with the private IP set in TELLYBOX_SETUP_BIND. Check the server firewall and whether guest Wi-Fi isolates devices. If you edited .env after starting Tellybox, run docker compose up -d --wait on the server to recreate the container. For the optional SSH-forward method, keep its terminal open and use its loopback address instead.

The container isn’t healthy

Run these in the project folder and read the error before changing anything:

docker compose ps
docker compose logs --tail=100 tellybox

No films or channels appear

Check that a media service is enabled, its connection test passes and its saved settings have been applied. Verify that the source itself has media or channels. Fresh installations start with every integration off.

Services on this server won’t connect

Select Runs on this server and check its port. The service must accept connections from Docker. A service in another container needs a published port or a shared Docker network.

Works here, but not on my phone

Check the LAN viewing settings above, your firewall, and whether guest Wi-Fi isolates devices. Docker publishes ports using its own networking rules. Keep the Linux server and Docker running while watching.

Jellyfin

Watch the films and series stored on your own disks.

Local films and seriesLocal episode librariesJellyfin playback and media segments
What it does & how to connect

Jellyfin organises your local files, supplies artwork and episode details, and prepares compatible video streams. Tellybox provides the browsing and playback interface.

You’ll need

An existing Jellyfin server, an API key and the ID of a dedicated viewer account with access to the libraries you want to share.

Without it

You can still use Dispatcharr for live TV and streamed films or series.

Use a dedicated viewer account. Tellybox viewers share its permitted libraries; do not use an administrator account for playback.

Bring live TV, a programme guide and your streamed catalogue together.

Live TV and programme guide24/7 channelsStreamed films and seriesRecordings and catch-up where available
What it does & how to connect

Dispatcharr manages your IPTV sources. Tellybox connects directly for live channels, a separate 24/7 area, on-demand films and series, and supported recording and catch-up features.

Your Jellyfin collection continues to work normally.

03 · REACH HOME

Optional remote access

For use only at home, skip this section. For internet access, run a small Linux relay with a public IP. It forwards HTTPS to the home server over Tailscale. Video processing stays at home.

Tailscale

A private connection between your home server and an optional public relay.

Requirements

Your own Tailscale account and approval of both machines.

No exit node or subnet router is needed. Tailscale does not make a public website by itself.

Official guide ↗

Caddy

The relay’s HTTPS front door, forwarding requests to Tellybox over the private connection.

Requirements

A hostname pointed at the relay and web ports allowed by its firewall.

Management stays separate from the public viewing route. Existing Caddy sites must be preserved.

Official guide ↗

Your relay shows the current public address and checks that it reaches this Tellybox server. Existing relays are recognised from applied settings; you do not need to install them again.

Set up from the browser

In installation settings, open Your relay → Set up a new relay. Enter the fresh Ubuntu 24.04 server’s SSH address, user and port, the public hostname and your home Tailscale IP. Choose a dedicated private SSH key and paste its verified known-hosts entry. The account needs passwordless sudo.

Save, select Check connection, then Review setup. Read the proposed changes and type the hostname to begin. Follow the Tailscale approval URL in the progress panel, then run setup again. No exit node is enabled. The helper leaves DNS and firewall changes to you.

Keys remain in the private configuration volume with restricted file permissions. They are never sent back to the browser. Include that volume only in encrypted backups. Existing Caddy sites are refused.

Alternative: use the CLI

The same helper can run from your computer if you prefer not to store an SSH key in Tellybox.

  1. Install Tailscale on the home server and approve it in your own account. No exit node is needed.
  2. Set TELLYBOX_RELAY_BIND to the home server’s Tailscale IP and recreate the Tellybox container. Permit only the intended relay to reach port 8083 using tailnet access rules.
  3. Copy relay/example.json to an ignored private/relay.json. Enter the hostname, SSH host/user/port, absolute key and known-hosts file paths, and the home Tailscale IP.
  4. Verify the relay’s SSH host-key fingerprint through the provider console. The helper uses strict host-key checking; an unverified scan is not proof of identity.
node relay/setup.mjs plan private/relay.json
node relay/setup.mjs check private/relay.json
node relay/setup.mjs install private/relay.json watch.example.com

Use your own hostname as the last argument. The installer prints a Tailscale sign-in URL; approve it in the same account as the home server, then rerun. It installs the relay only after the private home health check succeeds.

The helper refuses to replace an existing Caddy installation. For a shared host, generate the proposed block with node relay/setup.mjs site private/relay.json and have its administrator integrate it. Existing sites, firewall rules, public SSH and the home application are not changed by the helper.

Finish DNS and trust

  1. Create an A record for your chosen hostname pointing to the relay’s public IPv4. Remove any stale AAAA record unless IPv6 is configured.
  2. Allow TCP 80 and 443 in the provider and host firewalls. Caddy obtains and renews HTTPS certificates.
  3. In Tellybox installation settings, set the public HTTPS origin and add the relay’s exact Tailscale IP to trusted proxies. Apply when ready.
  4. Configure remote email access or the viewing password, approve a test account, and test from mobile data. Check that the viewing address cannot reach installation settings and that forwarded IPs identify the client.

Port 8083 is the authenticated remote entry. Never point a public relay at the login-free local port 8082. Home-IP recognition is optional; only enable it with a trusted relay and a working HTTPS public-IP check endpoint.

Remote viewing controls

Each approved account has its own allowance and screen limit. Open Settings → People, choose Manage, then Viewing & downloads.

  • Remote screens at once - choose Unlimited, 1, 2 or 3. Paused remote playback keeps its screen. At the limit, the newest play request is refused: stop another screen, then try again. Downloads do not count.
  • Viewing time - daily minutes reset at midnight UK time; total minutes stay until you reset them. Remote playback uses time. Local LAN and recognised home viewing are excluded. Parallel remote streams use time independently.
  • Local and admin priority - local LAN playback and admin or home-relay sessions are prioritised. Local LAN is exempt from the upload cap. Home over the relay still uses remote upload. Admin, local and home playback are exempt from the account screen cap.
  • Live and catch-up - live TV and 24/7 follow the live edge with no pause or seek. Catch-up, restart programme, recordings, films and episodes can pause and seek.
  • When time runs out - playback stops with the reason and a Back to browsing control. A single warning appears when about five minutes remain. Add time or reset the allowance before playing again.

Shared links show only their own link status. They never reveal another account’s remaining time or active screens.

Using Oracle’s free tier

A free-tier VM can be an optional relay where capacity is available. Choose only resources explicitly marked Always Free in your account. Do not assume a free trial credit makes a resource permanently free. Shapes, regional availability, network allowances and idle-instance rules can change.

Keep media storage and transcoding at home. Do not enable paid resources to work around a capacity shortage. Confirm the current limits in Oracle’s Always Free documentation before provisioning.

04 · WATCH

Your server. Your phone. Your TV.

Download the official Tellybox HomeLab app for your Android phone or Android TV, then enter your server address on first launch. The apps are proprietary, distributed separately from the server, and updated by Tellybox.

A home-only setup can use http://192.168.1.50:8082; remote viewing needs your own HTTPS address, such as https://watch.example.com. Replace these examples with your addresses.

Connect your phone or TV

Download for Android phoneDownload for Android TV

  1. Install the appropriate APK for your device.
  2. Enter the viewing address configured on your Tellybox server. Use HTTPS for a public domain; private network IPv4 addresses may use HTTP.
  3. If you use a public address, optionally enter the same local playback address set in installation settings. This lets compatible devices stream directly at home.
  4. Connect and follow the device-access screen. Disabled server features stay out of the app’s navigation.

To move the app to a different installation, clear its app data first. This removes its previous account and downloads, preventing credentials from crossing between servers.

Install on a TV from your phone

In the Android phone app, open Settings → Install on a TV. It gets the TV app directly from this HomeLab website and checks its package, version, file hash and signing certificate before sending it.

  1. Connect your phone to Wi-Fi on the same local subnet as the Android TV. The TV can use Ethernet. Guest Wi-Fi or client isolation can prevent devices from reaching each other.
  2. On the TV, open developer options and enable Wireless debugging, then open its pairing-code screen. Availability and menu names depend on the TV.
  3. On the phone, select Find a TV, choose your TV and enter its six-digit code. If needed, enter the pairing port shown beside the code and the separate connection port shown on the Wireless debugging screen.
  4. Select Connect and install. Keep the pairing screen open and approve any confirmation on the TV.
  5. Open Tellybox on the TV and enter your server address. Turn debugging off when finished.

Secure code pairing needs a compatible TV with Android 11 or later and a phone running Android 10 or later. If discovery cannot find it, Enter details manually accepts the TV’s local IPv4 address and ports.

Older TVs and connection details

Some older TVs offer network debugging instead of code pairing. Find an older TV asks permission before searching local port 5555. Selecting a device requires another confirmation because this older connection is unencrypted; approve the phone on the TV when prompted. A device appearing in the list is not proof that it is your TV.

Use a trusted home network. Code pairing requires TLS for installation, but the TV certificate is not pinned between the pairing and connection steps. The app’s Connection details and licences page explains the connection and includes its third-party licences.

No APK hosting is needed on your media server. The helper fetches the TV app for you; you still need to enable the TV’s developer options. Wireless pairing support varies by TV and needs testing on your device.

Updates, taken care of

The current Android app release is 0.26.8 (build 62). From version 0.25.1, the apps check this website for new versions automatically. Both updates and TV installation use the same signed releases, regardless of which media server you connect to. There is nothing to upload to your server and no Android SDK to install. Your viewing, account and favourites still belong to your chosen server.

Already installed version 0.25.0?

Download the newer phone or TV APK above and install it over your existing app. Don’t uninstall first: the package identity and signing key are unchanged, so your settings stay in place. Older installations that already publish a server update feed can keep it for this transition; new installations do not need it.

Administrator notifications

In installation settings, open Notifications and choose Standard Tellybox HomeLab, then save and apply. This is the recommended choice for the official app; no Firebase account or API key is needed. On an approved administrator’s Android phone, turn on admin alerts and allow Android notifications when asked.

Choose Off to leave push notifications disabled, or Custom Firebase if you want to manage your own Firebase project and credentials. Only the custom option shows those extra fields.

Notifications are optional. The shared gateway receives device registration information and opaque event IDs; the app fetches alert details from your own server. See privacy and data flow. Turning notifications off does not affect watching, and Android may delay background delivery. An iOS HomeLab app is not available in this release.

App downloads are covered by the official app terms. App source code is not included in the server repository.

05 · KEEP IT SAFE

Configuration backup & restore

The named configuration Docker volume contains installation settings, service credentials, accounts, favourites and caches. Media content remains in its source services. Back up Jellyfin, Dispatcharr, Seerr, Sonarr and Radarr separately if you need to restore those too.

  1. Stop the HomeLab container for a consistent configuration backup.
  2. Back up its named volume, your Compose file, .env and the exact source revision. Encrypt the archive: configuration includes credentials.
  3. On a replacement host, check out that revision, recreate the volume and restore its contents with the container user’s ownership.
  4. Start locally, verify the setup login and each service, then test remote routing before changing DNS.

Do not publish the configuration volume, bootstrap code, API keys, SSH keys, Firebase service account or signing keystore. Removing the container does not remove its named volume; docker compose down -v does.
